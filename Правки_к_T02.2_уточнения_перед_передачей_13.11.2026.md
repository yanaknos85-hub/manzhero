## 2. Правки

### 2.1. §2.2, «Альтернативные сценарии»

Сейчас — одна строка:

| Ситуация | Поведение экрана |
|---|---|
| GET не завершён / 404 / техническая ошибка | Не применять частичную карточку; показать соответствующую ошибку. Технический отказ не считается available=false. |

Нужно — две строки:

| Ситуация | Поведение экрана |
|---|---|
| Карточка загружается | Состояние «Загрузка карточки» по §6.7: индикатор, «Заказать» неактивна. Частичная карточка не применяется. |
| 404 или технический сбой при GET | Показать сообщение по §4.3. Частичная карточка не применяется. Технический отказ не считается available=false. |

### 2.2. §6.7, «Готовность и состояния интерфейса»

**Абзац о передаче в T02.3.**

Сейчас: «При актуальном available=true после повторной проверки экран передаёт в T02.3 полный снимок карточки, согласованную пару id/version из GET, fixedCost, проверенный момент, обязательные пользовательские поля, данные гостя при наличии и результат проверки. Изменение маршрута после этой проверки и до создания заявки не отслеживается. Заявка создаётся по проверенной версии и её fixedCost.»

Нужно: «Экран передаёт состояние в T02.3, если при получении ответа повторной проверки выполнены все условия:
- ответ available=true относится к текущим id/version и моменту поездки;
- обязательные поля, включая цель и данные гостя, валидны;
- для CAR_CHOICE успешная проверка занятости относится к текущему интервалу.

Передаются полный снимок карточки, согласованная пара id/version из GET, fixedCost, проверенный момент, обязательные пользовательские поля и данные гостя при наличии. Если хотя бы одно условие не выполнено, данные не передаются, а «Заказать» принимает состояние по текущим данным. Для отправки нужно новое нажатие. Изменение маршрута после этой проверки и до создания заявки не отслеживается. Заявка создаётся по проверенной версии и её fixedCost.»

**§6.2, пятый пункт списка.**

### 2.3. §5.3, «Данные гостя», и §5.1

Правило: поля ФИО у легкового TAXI заполняются по желанию. Если заполнено хотя бы одно поле, первое поле обязательно, а первый гость — гость-контакт. Пустые поля после первого допустимы. Требовать заполнения всех полей нельзя: счётчик задаёт общее число едущих, и если сотрудник едет сам с гостями, своё ФИО он не вводит.

**§5.3, первый абзац.**

Сейчас: «… Для TAXI данные гостя вводятся по желанию: для каждого указанного гостя или контакта ФИО обязательно, телефон гостя-контакта необязателен. …»

Нужно: «… Для TAXI данные гостя вводятся по желанию. Телефон гостя-контакта необязателен и без его ФИО не принимается. …»

**§5.3, абзац «Легковые классы TAXI».**

Сейчас: «Легковые классы TAXI. Штатный счётчик «Укажите количество пассажиров» от 1 до 4 показывается на экране заказа по ИМ всегда, независимо от «Совместной поездки». Блок «Данные гостя» показывает столько полей ФИО, сколько пассажиров указано. ФИО каждого гостя вводится одной строкой. Телефон вводится только для первого гостя.»

Нужно: «Легковые классы TAXI. Штатный счётчик «Укажите количество пассажиров» от 1 до 4 показывается на экране заказа по ИМ всегда, независимо от «Совместной поездки». Блок «Данные гостя» показывает столько полей ФИО, сколько пассажиров указано. Поля заполняются по желанию, каждое одной строкой. Если заполнено хотя бы одно поле, первое поле обязательно: первый гость — гость-контакт. Пустые поля после первого допустимы и не передаются. Телефон вводится только для первого гостя.»

**§5.3, абзац о commentForDriver.**

Сейчас: «ФИО остальных гостей легкового TAXI передаются в commentForDriver строкой «Пассажиры: ФИО2; ФИО3; ФИО4» в порядке ввода и только для указанных гостей. …»

Нужно: «ФИО остальных гостей легкового TAXI передаются в commentForDriver строкой «Пассажиры: ФИО2; ФИО3; ФИО4» в порядке полей и только для заполненных полей. …»

**§5.1, строка «Данные гостя · остальные гости», колонка «Преобразование».**

Сейчас: «Только легковые классы TAXI. Строка «Пассажиры: ФИО2; ФИО3; ФИО4» в порядке ввода. …»

Нужно: «Только легковые классы TAXI. Строка «Пассажиры: ФИО2; ФИО3; ФИО4» из заполненных полей в порядке полей. …»

### 2.4. Критерии приёмки

**AC-17**

**AC-32**

| | Сейчас | Нужно |
|---|---|---|
| Условие | «Оформить заказ в каждом режиме штатного блока «Кто пассажир?».» | «Для каждого режима штатного блока «Кто пассажир?» заполнить обязательные поля и нажать «Заказать».» |

**AC-35** — в условие и результат добавить проверку частичного заполнения. Проверку «пустое ФИО указанного гостя» заменить.

Условие: «Легковой класс TAXI. При выключенной «Совместной поездке» указать количество 3, ФИО трёх гостей, телефон первого гостя и комментарий водителю. Нажать «Заказать». Отдельно проверить:
- счётчик при включённой «Совместной поездке»;
- телефон не по маске +7;
- при количестве 3 заполнены первое и третье поля;
- при количестве 3 заполнены только второе и третье поля.»

Результат: «Счётчик отображается в обоих случаях. При количестве 3 показаны три поля ФИО. В данных для T02.3 ФИО и телефон первого гостя — в information.addContactFIO и information.addContactPhone. Первая строка commentForDriver — «Пассажиры: ФИО2; ФИО3», со следующей строки — комментарий пользователя. passengerCount = 3. fixedCost и привязка сохранены. С телефоном не по маске заказ не оформляется. При заполненных первом и третьем полях первая строка commentForDriver — «Пассажиры: ФИО3». При пустом первом поле заказ не оформляется до его заполнения.»

## 3. Этап 2: формулировка для §1.1

После того как правила будут зафиксированы в T02.3, T04.1 и T04.2, пятый и шестой абзацы §1.1 заменяются так:

«T02.2 переносит карточку на экран, хранит согласованную пару id/version, проверяет доступность на момент поездки и занятость выбранной машины, обрабатывает ошибки и поздние ответы. При нажатии «Заказать» экран передаёт проверенное состояние в T02.3 по §3.4. Формирование тела запроса, получение expected.segments и заполнение outcomeTariffId выполняются в T02.3. Расходный тариф такси определяет T04.2. Исключения проверок обычных заявок для заявок по ИМ определяет T04.1. Расходную стоимость проставляет бэкенд по T04.2. Ошибки T02.3 показываются на экране по §6.7. Путь на экране заказа не показывается, карты нет. Каталожный расчёт и выбор класса не выполняются; класс и тариф взяты из карточки, доступность тарифа проверяет availability.»
