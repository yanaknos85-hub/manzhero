# SBT-55 FavoriteRoute (T01.2): задачи и критерии приёмки

Редакция 06.11.2026. Основа: трекер разработчика от 03.11, T01.2 и T01.4 от 30.10.2026, ответы разработчика от 06.11.

## Исходные условия

- T01.4 — внутренний модуль FavoriteRoute, его делаем мы.
- Сетевой доступ к corporate, tariff-main, geo, geo-zones есть.
- Пользовательский JWT разработчик берёт из корпоративного кабинета; тарифы смотрит в выданном окружении.
- Код передаём Сберу, деплой выполняет Сбер.
- Решения заказчика не нужны: ночное окно GROUP_TRANSFER и правила DELETE определены в T01.2.

**Внешние блокеры, запрошены у Алексея 06.11:** Kafka (адрес брокера, права на чтение `service.request`, consumer group, тестовое сообщение); доступ к окружению FavoriteRoute на stage (адрес сервиса, база и конфиги на чтение, логи).

**Понадобится позже:** сервисный субъект для реестров (к подключению T05.1/T05.2). Пользовательский токен на внутренний URL по T01.2 не допускается.

### SBT-46 Реализовать API каталога отдельного сервиса
Блокер: доступ к окружению на stage.
1. POST, GET списка, GET карточки, PUT, DELETE, /calculate, /availability соответствуют OpenAPI T01.2; contract tests зелёные.
2. Неизвестные и output-only поля отклоняются с путём ошибки; тело больше 1 MiB — 413.
3. Список: status считается по поясу первой точки до пагинации; isActive=true по умолчанию.
4. Карточка: status и timeZone в ответе; checkTariff и checkRequests добавляют флаги только по запросу; чтение не пишет историю.
5. Сценарии проверены на stage с JWT из корпоративного кабинета; результат в комментарии.

### SBT-77 [FR-07] Редактирование и история версий
Внешних блокеров нет.
1. PUT увеличивает version и пишет в историю только изменённые поля; устаревшая version — 409 VERSION_CONFLICT.
2. Пояс первой точки пересчитывается только при смене первой точки.
3. Продление и перенос начала проверяют привязку тарифа.
4. Пересчёт через tariff-main проверен на stage; результат в комментарии.

### SBT-78 [FR-04] Серверный расчёт маршрута и выбор тарифа
Внешних блокеров нет.
1. /calculate возвращает варианты, failedTariffs, partial и partialSearch по T01.2; ошибки 422, 502, 503, 504 по каталогу ошибок.
2. В расчёт передаётся trafficJamScore=0; organizationId — только из доверенного контекста.
3. Каталог вариантов: два обхода /search (INCOME и TRANSITIONAL), все страницы, без приоритета договоров.
4. Точный расчёт и каталог проверены на stage на тарифах Манжерока; результат в комментарии.

### SBT-79 [FR-06] Защитить каталог от дублирующихся маршрутов
Внешних блокеров нет.
1. Дубль определяется по каноническому ключу: организация, точки по порядку, вид, класс, ночной признак, автомобиль для TRANSFER_CAR_CHOICE.
2. Пересечение периодов считается по поясу первой точки каждого кандидата (geo-zones), а не по поясу пользователя.
3. Конкурентное создание одинаковых маршрутов даёт одну запись.
4. Проверено на stage на маршрутах из разных поясов.

### SBT-80 [FR-08] Сроки действия и безопасная деактивация
Блокер: Kafka.
1. Availability проверяет isActive, включительный период и окно [06:00, 22:00) по поясу первой точки для TAXI и GROUP_TRANSFER.
2. DELETE: повтор — 204; активная связь — ACTIVE_REQUESTS_EXIST; неизвестный статус — REQUEST_STATUS_UNCLASSIFIED.
3. Проверяются известные связи; поздняя связь вызывает оповещение, строгий межсервисный запрет не требуется (T01.2).
4. Перечитывание заявок перед DELETE проверено на stage с заявками из Kafka.

### SBT-82 [FR-09] Сохранение маршрута с выбранным автомобилем
Внешних блокеров нет.
1. Для TRANSFER_CAR_CHOICE transportId обязателен, для остальных классов — null.
2. Пригодность автомобиля проверяется при создании, изменении и availability на дату поездки.
3. Ветка feature/t012-saved-binding-from-dev вмержена в dev, тесты зелёные.
4. Проверено на stage на тарифе TRANSFER_CAR_CHOICE с автомобилем.

## 2. Новые задачи

### [FR] JWT, роли и организация (corporate)
Задача 4 трекера; от неё зависят задачи 8–15. Внешних блокеров нет.
1. Публичные методы доступны с JWT ролей EMPLOYEE, ADMIN, ENGINEER; без роли — 403 FORBIDDEN.
2. Организация определяется через corporate GET с токеном пользователя; несколько организаций у data master — отказ, выбор первой не допускается.
3. Чужой маршрут по id — 404.
4. Роли перевозчика и диспетчера без одной из трёх ролей доступа не дают; сервисный токен в публичных методах не принимается.
5. Проверено на stage для каждой из трёх ролей. Если учётки какой-то роли нет — запросить.

### [FR] События заявок: Kafka service.request на stage
Задача 7 трекера. Блокер: Kafka.
1. Consumer читает `service.request` отдельной consumer group, при первом запуске — с начала истории.
2. Тестовая заявка со ссылкой на маршрут создаёт или обновляет строку связи; сброс ссылки удаляет строку; повтор события не создаёт дублей.
3. Невалидное сообщение диагностируется; offset подтверждается только после успешного применения.
4. GET с checkRequests=true и DELETE учитывают связь из события.
5. Сообщение, запись в БД и ответы API приложены в комментарии.

### [FR] Историческая версия маршрута для реестров
Задача 13 трекера. Блокер: сервисный субъект для реестров (к подключению T05.1/T05.2).
1. Внутренний метод доступен только сервисному субъекту с отдельным разрешением; пользовательский токен получает отказ.
2. Возвращается FavoriteRouteDto запрошенной версии без пересчёта цены и записи истории.
3. Чтение ограничено организацией; несуществующая версия — 404.
4. Сквозная проверка с реестром на stage.
