# Технические проверки И1–И8: ответ по коду, по стенду, что открыто

Вопросы взяты из раздела 8.2 «Технические проверки, которые выполняет команда». Колонки таблиц:
- «По коду» - ответы соседней задачи от 16.10.2026. Пометка «Уточнение» - наш разбор исходников, он дополняет или поправляет ответ.
- «По стенду» - наши наблюдения 08.10, 12.10 и 13.10.2026. Подробности в `НАХОДКИ_FavoriteRoute.md` и `вопросы/Стенд_по_проверкам_И1-И8.md`.

Версия сборки стенда нигде не зафиксирована. Прочерк означает, что данных нет.

## И1. Шлюз, transport_core, role_check_starter

| Проверка | По коду | По стенду | Открыто |
|---|---|---|---|
| Rewrite для корня и `/calculate` | Маршрута для сервиса нет. Все маршруты шлюза устроены как `Path=/api/<ресурс>/**` + `RewritePath`. По этому образцу `/api/favorite-routes/` → `/`, `/api/favorite-routes/calculate` → `/calculate`, а путь `/api/favorite-routes` без «/» не переписывается и даёт 404. Варианта два: «/» в контракте или своя регулярка | Клиент ходит через шлюз по образцу `/api/<ресурс>/...`: тарифы, geo, организации. Путь без «/» не проверялся | Выбор варианта (T01.2), проверка после развёртывания |
| ExceptionBody | Стоит `@JsonInclude(NON_EMPTY)`: пустой `problems` и `entity = null` не выводятся. `problems` - Set, ошибки без поля схлопываются в одну. `entity.id` есть | Тело ошибки не фиксировалось: при 417 видели только «address not found» в консоли клиента | Контрактные тесты |
| Страница | В transport_core свой `Page`: `content`, `pageData`, `sortData`, одна сортировка. Его используют corporate и limits, остальные сервисы - Spring `Page`. Рекомендация - платформенный | Search тарифов отдаёт Spring Page: нумерация с 0, параметры и в строке запроса, и в теле | Выбор формата (T01.2) |
| Локальный code и диагностические поля `/calculate` | В ответе не рассмотрено. Про code есть ответ архитектора А11 от 15.10: поле в ExceptionBody или наследник | - | Всё |
| Доступ к `/allow` | `PUT /allow` и `GET /allow/{role}` лежат в корне сервиса. Через шлюз они доступны как `/api/favorite-routes/allow`, защищает их только запрет по умолчанию в стартере | Не проверялось | Проверка доступа |
| Версия, commit, OpenAPI, контрактные тесты | Исходники: шлюз сборки 230424-1, transport_core 4.22-SNAPSHOT. Совпадение со стендом неизвестно | Версия и коммит стенда не зафиксированы | Всё |

## И4. Тарифы и договоры

| Проверка | По коду | По стенду | Открыто |
|---|---|---|---|
| DTO тарифов и договоров | Поля карточки тарифа трансфера. Договор: `startDate` и `endDate` типа `LocalDate`, `active`, `contractType`, `regionIds`, `organizationIds` - список | Элемент search: класса, признаков трансфера, цены и периода нет. У договора есть «Действует с — по» | - |
| Организация договора и организация подразделения | Договор проверяется по вхождению организации в `organizationIds`. Организация подразделения отдельно не рассмотрена | - | Организация подразделения тарифа |
| Четыре признака трансфера, null и default | `vip` - boolean, остальные три - Boolean. В запросе все false, отбор по точному равенству, поэтому тариф с null не находится. Дефект: `bugOversized` сравнивается с `animal`. Расчёт по tariffId признаки не фильтрует. **Уточнение:** через API и кабинет признаки записываются как false, null возможен только в старых данных | VIP виден только у «Выбора автомобиля». null не проверяли | Есть ли null в данных |
| Даты и пояс договора | `LocalDate` без пояса | Три договора с истёкшим сроком остаются «Активный», их тарифы активны. У трансфера можно менять дату окончания договора, дата начала заблокирована. У такси период только для чтения | В каком поясе сравнивать (И3) |
| Режимы CalculationBundle, PRICE_ONLY без geo | Режимов нет, это понятие T01.4. Расчёт принимает `distance` и `time` готовыми, значит без geo он возможен | В запросе расчёта `distance` и `time` взяты клиентом из ответа geo | Контракт T01.4 |
| Частичные отказы | Ответ один. Сбой на одном тарифе роняет весь вызов, частичный результат - только из нескольких своих вызовов | - | - |
| Машина у разных перевозчиков | Последний тариф перезаписывает карту. Расписание запрашивается у перевозчика первого тарифа, в ответе только `id` и `cost`. Если тарифа нет в карте - 500. **Уточнение:** оба расчёта ищут тарифы только организации из запроса | Карточка автомобиля привязывает машину к организациям и подразделениям. Машина у нескольких перевозчиков не проверялась | Какой тариф брать (T01.4) |
| Режим без временных надбавок | Такого режима нет: коэффициент времени применяется всегда, праздники не учитываются. «Для такси - доработка тарифного сервиса в T01.4» - **расходится с границей 08.10**. **Уточнение:** базовой цены в ответе нет; минимальные стоимости применяются до умножения на коэффициент, округление до рубля - после | Коэффициенты времени 1,00, в форме недоступны. Задаются загрузкой прайса | Способ решения и согласование границы |
| Изменение тарифа во время расчёта | Тарифы правятся на месте, версий нет | Форма правки сохраняет тариф: меняются территория, период и цены. Тест не проводился | Тест |
