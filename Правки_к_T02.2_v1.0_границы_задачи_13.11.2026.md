# T02.2 v1.0: правки по границам задачи

Редакция 13.11.2026. Номера разделов и критериев — по v1.0.

Правки идут в два этапа.
- **Этап 1 — вносим сейчас.** Это то, что относится к виджету, событиям заявки, аудиту, диспетчерской и серверным проверкам, а также переформулировка критериев приёмки.
- **Этап 2 — вносим после того, как правила зафиксируют спецификации ответственных задач** (раздел 3). Тогда сокращаем их описание в T02.2.

Контракт передачи в T02.3 (§3.4, строка «T02.2 → T02.3», и §5.1) остаётся в T02.2. В нём остаются `fixedCost`, метрики, данные гостей и формат строки «Пассажиры: ФИО2; ФИО3».

Данные гостя у трансфера: остаётся штатное поведение. Блок «Контакты основного пассажира» всегда включён, нужно указать ФИО или отметить «Нет пассажира», телефон обязателен. §5.3 в этой части не меняется. Формат телефона `+7` не меняется. Вопрос о других форматах уходит заказчику отдельно.

## 4. Для согласования

**Отличия от декомпозиции от 28.10:**
1. Виджет передаёт только id (декомпозиция, задача 5: id и версия). Версия берётся из GET карточки.
2. Отдельный экран заказа вместо существующей формы (задача 6). Экран переиспользует штатные блоки полей и сохранение.
3. Матрица переключения из задачи 8 (задача 6) применяется с учётом того, что точки на экране только для чтения. На экране изменяются только пользовательские поля, а fixedCost и привязка сохраняются. Смена момента повторяет availability. Переход на динамический расчёт возможен только при изменении созданной заявки (T04.2).

**Распределение работ:** T02.2 описывает WEB, T03.2 — МП. Одинаковое предзаполнение в WEB и МП — требование сквозной приёмки.
