# SBT-55: критерии приёмки для открытых задач

Вставить в описание или комментарий каждой задачи. SBT-8 и SBT-81 — закрыть.

## SBT-46 Реализовать API каталога отдельного сервиса
1. POST, GET списка, GET карточки, PUT, DELETE, /calculate, /availability соответствуют OpenAPI T01.2; contract tests зелёные.
2. Строгий JSON: неизвестные и output-only поля отклоняются с путём ошибки; тело больше 1 MiB — 413.
3. Список: фильтр status считается по поясу первой точки до пагинации; isActive=true по умолчанию.
4. Карточка: status и timeZone в ответе; checkTariff и checkRequests добавляют флаги только по запросу; чтение не пишет историю.
5. Проверено на стенде с реальным JWT/corporate (блокер — задача «[FR] JWT, роли и организация»).

## SBT-77 [FR-07] Редактирование и история версий
1. PUT увеличивает version, пишет в историю только изменённые поля; устаревшая version — 409 VERSION_CONFLICT.
2. Пояс первой точки пересчитывается только при смене первой точки.
3. Продление и перенос начала проверяют привязку тарифа.
4. Пересчёт через реальный T01.4 проверен на стенде (блокер — T01.4).

## SBT-78 [FR-04] Серверный расчёт маршрута и выбор тарифа
1. /calculate возвращает варианты, failedTariffs, partial и partialSearch по T01.2; ошибки 422/502/503/504 по каталогу.
2. В расчёт уходит trafficJamScore=0; организация берётся только из доверенного контекста.
3. Поиск охватывает INCOME и TRANSITIONAL, несколько страниц, без приоритета договоров.
4. Live-проверка с реальным T01.4 (URL, JWT, тариф своей организации) зафиксирована в комментарии.

## SBT-79 [FR-06] Защитить каталог от дублирующихся маршрутов
1. Дубль определяется по каноническому ключу (организация, точки по порядку, вид, класс, ночной признак, автомобиль для TRANSFER_CAR_CHOICE).
2. Пересечение периодов считается по поясу первой точки каждого кандидата, а не актора.
3. Конкурентное создание одинаковых маршрутов даёт одну запись.
4. Пояс кандидатов берётся из T01.4 (блокер).

## SBT-80 [FR-08] Сроки действия и безопасная деактивация
1. Availability проверяет isActive, включительный период и дневное/ночное окно [06:00, 22:00) по поясу первой точки для TAXI и GROUP_TRANSFER.
2. DELETE: повтор — 204; активные связи — ACTIVE_REQUESTS_EXIST; неизвестный статус — REQUEST_STATUS_UNCLASSIFIED.
3. Строгий межсервисный запрет не требуется: проверяются известные связи, поздняя связь вызывает оповещение (T01.2).
4. Перечитывание заявок и N/M проверены с T04.1 на стенде (блокер).

## SBT-82 [FR-09] Сохранение маршрута с выбранным автомобилем
1. Для TRANSFER_CAR_CHOICE transportId обязателен, для остальных классов null.
2. Пригодность автомобиля проверяется при создании, изменении и availability на дату поездки.
3. Ветка feature/t012-saved-binding-from-dev вмержена в dev, тесты зелёные.
4. Проверка автомобиля через реальный T01.4 на стенде (блокер).
