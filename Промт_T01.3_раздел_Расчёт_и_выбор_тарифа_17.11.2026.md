# Промпт: T01.3, раздел «Расчёт и выбор тарифа»

Ты системный аналитик проекта «Избранные маршруты» АС «СберТранспорт», Манжерок. Подготовь новый раздел спецификации T01.3 «UI справочника избранных маршрутов» (TRANSPORT-45587) — «Расчёт и выбор тарифа». Раздел описывает, как в модальном окне создания и изменения маршрута выполняется предварительный расчёт, как пользователь выбирает тариф из выпадающего списка и вводит фиксированную цену.

## Источники

Приложены:
- T01.3, раздел «Ввод точек маршрута» (версия 14) — образец стиля и смежные правила. Его не меняй.
- T01.2 FavoriteRoute (согласованная редакция от 30.10.2026 с правкой 17.11) — контракт API. Его не меняй, правила бери из него: «Предварительный расчёт маршрута», «Создание маршрута», «Изменение и продление маршрута», «Расчёт и пересчёт», «Правила вызова API», «Примеры сообщений пользователю».
- БТ «Справочник избранных маршрутов».
- Макеты «Добавить маршрут» и «Редактировать маршрут».

## Согласованные решения (не пересматривать)

1. Порядок: сначала расчёт, потом выбор. Отдельного списка тарифов без цены в T01.2 нет, расчёт по заранее выбранному tariffId /calculate не принимает. Выпадающий список «Тариф» заполняется вариантами из ответа /calculate (массив tariffs), у каждого варианта уже есть рекомендуемая стоимость.
2. Тариф выбирает пользователь (решение заказчика 17.11). После расчёта поле «Тариф» пустое. Экран не выбирает вариант сам, даже если он один.
3. Пересчёт. Если в новом расчёте есть вариант с теми же tariffId, serviceClass и transportId, выбор пользователя сохраняется, а рекомендуемая стоимость обновляется по новому расчёту. Если такого варианта нет, поле «Тариф» очищается, и экран просит выбрать тариф заново.
4. Поле «Стоимость» (fixedCost):
   - при создании маршрута пустое до ручного ввода цены по прайсу;
   - рекомендуемая стоимость показывается отдельно, только для чтения;
   - при изменении маршрута в поле показывается сохранённая цена по прайсу;
   - смена тарифа и повторный расчёт значение поля не перезаписывают;
   - цена может быть ниже рекомендуемой (решение заказчика); правила формата и диапазона — из T01.2.
5. Тексты сообщений FavoriteRoute экран показывает как получены (message), причину определяет по HTTP-статусу и code. Технические ошибки расчёта и сохранения уже описаны в разделе «Ввод точек маршрута» («Проверки и ошибки»): ссылайся на него, не дублируй.
6. Изменение только названия, фиксированной цены или периода действия нового расчёта не требует. Изменение точек, координат или ожидания сбрасывает расчёт (раздел «Ввод точек маршрута»).

## Что описать

1. Входные данные расчёта: какие поля формы уходят в /calculate (точки — по разделу «Ввод точек маршрута», вид сервиса, класс, признак ночного тарифа). transportId в запрос не передаётся: для «Выбора автомобиля» варианты уже содержат автомобиль. Когда расчёт доступен и как запускается (кнопка «Рассчитать», после расчёта — кнопка обновления).
2. Изменение вида сервиса, класса или ночного признака после расчёта: прежние варианты не соответствуют запросу, нужен новый расчёт; выбор сохраняется по решению 3, если вариант остался.
3. Выпадающий список «Тариф»:
   - источник — tariffs из ответа /calculate, порядок — как в ответе;
   - подпись варианта, по которой варианты различимы: номер тарифа, перевозчик или договор (если есть), рекомендуемая стоимость; для «Выбора автомобиля» — ещё госномер и марка из transportInfo. Варианты одного класса с одинаковой ценой должны различаться;
   - в расчёте могут быть варианты одного класса по доходному (INCOME) и транзитному (TRANSITIONAL) договорам — T01.2 возвращает оба типа без приоритета. Подпись должна их различать по номеру договора (contractNumber) и перевозчику (contractorName). Типа договора в ответе /calculate нет — не добавляй его и не выводи из других полей;
   - что попадает в запрос сохранения: tariffId выбранного варианта, для «Выбора автомобиля» — его transportId.
4. Результаты расчёта и действия экрана:
   - успешные варианты без отказов;
   - пустой результат (200, tariffs=[], partial=false) — сохранить нельзя, показать сообщение, что подходящего действующего тарифа нет и его нужно завести (по БТ сохранение без тарифа блокируется);
   - частичный результат (partial=true или partialSearch=true) — показать успешные варианты и предупреждение, что список может быть неполным; отказы вариантов из failedTariffs — по их message;
   - 422 с failedTariffs (CALCULATION_OPTIONS_REJECTED или один нетехнический код) — показать message и причины по вариантам.
5. Рекомендуемая стоимость: когда пустая, когда показывается значение выбранного варианта, что показывается после сохранения (по T01.2 окончательная recommendedCost берётся из ответа сохранения).
6. Сохранение:
   - «Сохранить» доступна, когда выбран вариант актуального расчёта и введена фиксированная цена (плюс проверки раздела «Ввод точек маршрута»);
   - 400 TARIFF_INVALID или TRANSPORT_INVALID при сохранении: показать message, очистить выбор и потребовать новый расчёт.
7. Изменение сохранённого маршрута:
   - при открытии в поле «Тариф» показан сохранённый тариф карточки (номер, для «Выбора автомобиля» — автомобиль), расчёт не запускается;
   - если параметры расчёта не менялись, маршрут сохраняется без нового расчёта;
   - если пользователь хочет сменить тариф или изменил параметры расчёта — расчёт и выбор по решениям 2–3.
8. Критерии приёмки. Продолжи нумерацию раздела «Ввод точек маршрута»: начни с AC-T01.3-29. Обязательно покрой решения 1–4, пустой и частичный результат, «Выбор автомобиля», изменение маршрута без нового расчёта, 400 TARIFF_INVALID при сохранении.
